## 2. H.264 vs H.265 심층 비교 분석

### 🔍 1) CPU 디코딩 연산 비용 (H.264의 우세)
- **800x448 서브스트림**: H.264(`0.84ms`) vs H.265(`1.59ms`) $\rightarrow$ **H.265가 약 1.89배 더 많은 CPU 연산 소요**
- **2592x1520 메인스트림**: H.264(`6.19ms`) vs H.265(`10.69ms`) $\rightarrow$ **H.265가 약 1.73배 더 많은 CPU 연산 소요**
- **원인**: H.265(HEVC)는 H.264 대비 압축률이 40~50% 뛰어난 대신, 가변 코딩 트리 유닛(CTU 64x64), 35개의 인트라 예측 모드, SAO(Sample Adaptive Offset) 루프 필터링 등 알고리즘 복잡도가 높아 **CPU 소프트웨어 디코딩 시 연산 부담이 약 1.7~1.9배 증가**합니다.

### 🔍 2) YUV $\rightarrow$ RGB 스케일링 변환 비용
- **800x448**: `~0.21 ms`
- **2592x1520**: `~2.2 ~ 2.4 ms`
- 스케일링 시간은 코덱 압축 방식과 무관하며, 화면 픽셀 수(해상도)에 정비례합니다.

### 🔍 3) 현재 시스템 권장 구성 (CPU 환경)
- 현재와 같은 **CPU 디코더 환경에서는 H.264 (`profile4` 4분할 / `profile2` 1채널 확대)** 조합이 디코딩 지연 시간이 가장 짧고 프레임 드랍이 없어 최상의 성능을 발휘합니다.

## 4. Latency를 어떻게 줄였는가? (핵심 최적화 기법 5가지)

### ① 동적 프로파일 분기 (Dynamic RTSP Profile Switching)
- 4분할 모드에서는 가벼운 **`profile4` (800x448 서브스트림, 1.06ms)**을 수신하고, 1채널 확대 시에만 **`profile2` (2592x1520 메인스트림)**로 동적 전환하여 4개 채널 동시 디코딩에 따른 CPU 과부하 원천 차단.

### ② FFmpeg 초저지연 프로빙 및 제로 버퍼링 (`nobuffer` & `low_delay`)
- `probesize`=64KB, `analyzeduration`=100ms, `fflags=nobuffer`, `AVFMT_FLAG_NOBUFFER` 적용으로 스트림 분석 딜레이와 수신 버퍼 딜레이 제거.

### ③ H.264 / H.265 디코더 플래그 최적화
- `AV_CODEC_FLAG_LOW_DELAY`(B-프레임 딜레이 제거) 및 `AV_CODEC_FLAG2_FAST`(고속 루프 필터)를 적용하여 프레임 도착 즉시 1ms 이내 디코딩 완료.

### ④ 마지막 프레임 유지 (Seamless Freeze Transition)
- 프로파일 전환 핸드셰이크 중 화면을 검게 비우지 않고 **이전 프레임을 자연스럽게 Freeze 상태로 유지**하다가 새 스트림의 첫 I-Frame이 준비되는 즉시 교체하여 체감 깜빡임과 블랙아웃 0초화.

### ⑤ SWS 스케일러 컨텍스트 캐싱 및 메모리 재사용
- `sws_getContext` 및 RGB 버퍼를 매 프레임 재할당하지 않고 영구 캐싱하여 메모리 복사 오버헤드 제거 (스케일링 0.22ms).

## 5. 향후 GPU 하드웨어 가속(D3D11VA / DXVA2 / NVDEC) 도입 시 기대 효과

| 비교 항목 | CPU 디코더 (현재) | GPU 하드웨어 가속 (향후) | GPU 도입 시 핵심 이점 |
| :--- | :---: | :---: | :--- |
| **H.264 2592x1520 디코딩** | `6.19 ms` | **`~0.8 ms`** | GPU 전용 비디오 디코더 엔진(NVDEC/QSV) 활용 |
| **H.265 2592x1520 디코딩** | `10.69 ms` | **`~1.0 ms`** | **H.265의 높은 압축률(대역폭 50% 절감)을 지연 없이 활용 가능** |
| **YUV $\rightarrow$ RGB 컬러 변환** | `2.43 ms` | **`~0.05 ms`** | GPU Direct VRAM 텍스처 바인딩 (Zero-Copy) |
| **호스트 CPU 점유율** | 약 5 ~ 15% | **`0 ~ 1%` 수준** | CPU를 라이다 점군 처리 및 AI 추론에 100% 집중 가능 |
